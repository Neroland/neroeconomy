# Changelog

## [Unreleased]

### Changed

- **NeroEconomy has its own creative tab** (`itemGroup.neroeconomy`): its blocks, the Credit Chip and
  the Trader's Handbook moved out of Neroland Core's shared tab, which now holds only Core's items.
- `en_us.json` is sorted by key again (seven block/item keys at the top were out of order, which
  failed `LangAuditTest`).

### Fixed

- Crafting recipes now unlock in the recipe book the first time a player picks up one of their ingredients (9 recipe-unlock advancements, generated by `tools/gen_recipe_unlocks.py`; run it again after adding a recipe, `--check` verifies).
- **Block and loot drops work as intended on Minecraft 26.3** (NeoForge, Fabric and Forge). Minecraft
  26.3 changed the loot-table file format and silently ignores the old one, so conditions and drop
  modifiers (explosion survival, door/slab block-state checks, drop counts, random chances) were skipped.
  The 26.3 builds now ship every loot table in the new format. 26.1.2 and 26.2 were not affected.

## [0.4.0-beta.1] - 2026-10-11

A content release that **requires Neroland Core 1.15.0** (was 1.13.0): NeroEconomy now opens progression
gates for offline players and publishes its threshold crossings with a source, both Core 1.15.0 APIs.
Worlds and configs from 0.3.x load unchanged; one optional section (`perks`) is added to the combined
store, and the cross-mod API is unchanged (`SiblingEconomy.API_VERSION` is still 1).

### Added

- **A quest chapter.** Ships a NeroQuests quest pack — chapter `neroeconomy:traders_ledger` "Trader's
  Ledger", 15 quests (3 server-wide world-log entries) — that appears in the quest book when
  NeroQuests is installed; inert otherwise, no dependency in either direction. The quests follow the
  milestone gates below, two `economy` objectives (256 goods sold, 5000 credits earned), the Merchant
  Stall craft, and the `reserve`, `market_shock` and `sector_index` channels for the world log.
- **Three more milestone gates**, scope `player`: `neroeconomy:first_auction_win` (an auction settles in
  your favour), `neroeconomy:first_delivery` (you fulfil a contract or delivery job, a House's included)
  and `neroeconomy:first_dividend` (a company you hold pays you a dividend). Nine milestones in all.
- **Quest hooks.** Two record gates a quest pack's `mod_hook` reward can open, `neroeconomy:hook/fee_waiver`
  and `neroeconomy:hook/handbook_page`, listened for on Core's gate events. The first waives the player's
  next listing fee on an order they place themselves (a single flag, never a credit, held at most once at a
  time, kept in the new `perks` section); the second opens the next **Trader's Note** for them. A hook that
  opens while the player is away, or while the economy is frozen, is delivered at their next join.
- **Trader's Notes.** Four extra Handbook pages, one each at the end of the market, shops, Merchant
  Houses and jobs chapters, revealed one at a time by the `handbook_page` hook through player-scope
  gates `neroeconomy:handbook/<id>`. The book still reads nothing from the server: the client learns
  which notes are open from Core's own gate sync.

### Changed

- **Milestone gates open for offline players.** A milestone reached while its player is away now opens
  its gate within a second, instead of waiting for them to join (Core 1.15.0's offline gate API).
- **Threshold crossings carry their source.** The `reserve`, `house_stock`, `market_shock` and
  `sector_index` channels are published with `neroeconomy` as the source mod, so a listener using Core
  1.15.0's sourced bus can tell them apart from another mod's; the crossings themselves are unchanged.
- **Privacy.** The `perks` section holds one flag per player (a pending fee waiver) under their UUID; it
  is exported (`perks`) and erased with the player. The Trader's Note gates live in Core's gate store
  like every other progression gate. See [PRIVACY.md](PRIVACY.md).

## [0.3.2-beta.1] - 2026-10-11

A hotfix release with no gameplay, config or save-format changes. Worlds and configs from 0.3.x load

### Fixed

- **Game no longer fails to start with NeroSpace and NeroLogistics installed.** NeroEconomy declared
  `ordering = "AFTER"` on its optional siblings, which together with NeroSpace and NeroLogistics ordering

  and Forge; siblings still load after NeroEconomy.

## [0.3.0-beta.1] - 2026-10-10

NeroEconomy 0.3: a living economy. This release adds trading (an order book, direct trade, offers and
auto-trade rules), a private Vault, an exchange with Savings Bonds and practice mode, autonomous
Merchant Houses, a Reserve that every system payout comes from, one Economy Hub screen with
walkthroughs and a Trader's Handbook, and companion-app link schema 2 for offline trading. It changes
how credits are created, moves all economy state into one store and adds 78 config keys, so
operators should read **Changed** and **Migration** before upgrading. This is a beta: back up your
world before the first start, because the 0.2 stores are adopted into the combined store. The October
2026 audit remediation that shipped in the same release is kept below, under its own heading.

### Added

- **The Reserve.** A system account that every payout comes out of and every fee goes into. It is
  filled once (`reserveInitial`), topped up daily (`reserveDailyMint`, up to `reserveCap`) and bounded
  by daily budgets for Merchant Houses, the exchange and other mods. A payout that the Reserve or
  its budget cannot cover is refused before anything moves. Operators see circulation, Reserve,
  escrow, exchange, minted and burned today with `/eco admin supply` and on the Admin tab.
- **The Vault.** Every player has a private store of goods (`vaultStacks`, 54), opened at the Bank
  Terminal. Purchases made while away, refunds, expired orders and offers, and shop stock all
  deliver to it.
- **Order book.** Sell and buy orders that match each other (best price first, oldest first, at the
  resting order's price), a Trading Terminal search that shows orders and shops side by side, and
  the commands `/eco order sell|buy|cancel|mine`. A buy order escrows its credits.
- **Direct trade** (`/trade <player>`, or sneak-use on a player): a two-sided window of nine stacks and
  a credit amount per side, where any change clears both confirmations and the contents freeze for
  three seconds before one atomic swap. **Offers** send items and credits to a named player, who
  answers in game or in the app: `/eco offer send|list|accept|decline|cancel|mute`.
- **Auto-trade rules** (`/eco rule ...`) that keep placing book orders while the owner is offline,
  and the **Auto-Trader** block, a vanilla container that hoppers and ducts can feed. Each rule
  reports one status.
- **The exchange.** Twelve fictional companies, an index fund and 1-, 3- and 7-day Savings Bonds,
  at the Exchange Terminal and with `/eco invest ...`. Published price model, a spread, a fee, a
  holding period, position limits, dividends, splits, daily limits with a halt, and a
  **practice mode** with play credits that cannot touch the ledger.
- **Autonomous economy.** Merchant Houses and the Merchant Stall, commodity pricing with daily
  caps and price pressure, reference prices that follow player trade, Reserve-funded auctions, jobs
  and server bounties, a simulation that advances in economy time and catches up after a pause
  (`simCatchUpMaxHours`), and an arbitrage guard (`/eco admin reload-check`).
- **Data packs:** companies (`stocks/`), commodities (`commodities/`, with `compat/<modid>.json`),
  Merchant Houses (`houses/`), server bounties (`bounties/`), arbitrage-guard conversions (`guard/`)
  and the item tag `neroeconomy:never_commodity`.
- **The Economy Hub** with tabs for Wallet, Vault, Market, My orders, Invest, Trade, Jobs, Auctions,
  Shop and (level 3) Admin; `/eco hub [tab]`; a tooltip on every control; a **Show me** walkthrough
  per tab on sample data with a permanent DEMO banner; and the **Trader's Handbook**, given once on
  first join (`giveHandbookOnFirstJoin`) and craftable from a book and a gold nugget.
- **Operator tools:** `/eco admin supply|stocks|houses|reload-check|health|market close|open|sim`, an
  operator market freeze, and a freeze of the whole economy when its store is missing or
  unreadable. The gallery now builds eleven clusters, one per system, from sandboxed data.
- **Companion app (link schema 2).** New sections `summary`, `orders`, `vault`, `stocks`, `portfolio`,
  `offers`, `jobs` and `auctions`, topics `orders`, `offers`, `portfolio` and `alerts`, and actions
  `order_place`, `order_cancel`, `rule_set`, `rule_delete`, `rules_pause`, `stock_buy`, `stock_sell`,
  `bond_buy`, `pay`, `offer_send`, `offer_accept`, `offer_decline`, `offer_cancel`, `claim_collect`,
  `vault_deposit` and `vault_withdraw`. Everything except the two vault moves works while the player
  is offline. Ten more fixed alerts (offers, rules, bonds, dividends, delisting, filled orders, a
  full vault).
- **Config keys** (defaults in brackets):
  - Reserve, budgets and faucets: `startingBalanceVestMinutes` (30), `reserveInitial` (250000), `reserveDailyMint` (5000), `reserveCap` (2000000), `npcDailyBudget` (20000), `exchangeDailyBudget` (15000), `siblingDailyBudget` (5000), `creditChipDailyBudget` (3000).
  - Fees and trading: `marketFeePercent` (2), `listingFee` (1), `auctionFeePercent` (5), `exchangeFeePercent` (1), `tradeTaxPercent` (0), `tradeRangeBlocks` (16), `offerDurationHours` (48), `maxOffersPerPlayer` (16), `maxRulesPerPlayer` (8), `ruleDailyValueCap` (10000), `vaultStacks` (54).
  - Simulation and Merchant Houses: `autonomousEconomy` (true), `simStepMinutes` (10), `simCatchUpMaxHours` (72), `commoditySpreadPercent` (10), `arbitrageGuardDepth` (3), `referenceDriftStepPercent` (1), `referenceBandMinPercent` (50), `referenceBandMaxPercent` (200), `referenceMinTradeValue` (16), `referenceAccountDailyCap` (2000), `referenceMinPairs` (3), `referenceDriftDayPercent` (10), `npcAuctionsPerDay` (4), `npcAuctionHours` (24), `houseJobPremiumPercent` (15), `houseJobsPerHouse` (2), `houseJobHours` (24), `systemBountiesPerDay` (2), `debugFastSim` (false).
  - The exchange: `exchangeEnabled` (true), `exchangeStepLimitSteadyPercent` (2), `exchangeStepLimitRiskyPercent` (6), `exchangeDayLimitSteadyPercent` (10), `exchangeDayLimitRiskyPercent` (40), `exchangeHaltSteps` (6), `exchangeReversionPercent` (0.05), `exchangeVolumeNudgeCapPercent` (0.5), `exchangeVolumeScale` (2000), `exchangeVolumePairCap` (250), `exchangeVolumeAccountCap` (1000), `exchangeShockStepPercent` (1), `exchangeFloorPercent` (5), `bondRate1DayPercent` (0.8), `bondRate3DayPercent` (3), `bondRate7DayPercent` (8), `exchangeSpreadSteadyPercent` (1), `exchangeSpreadRiskyPercent` (2), `exchangeSpreadIndexPercent` (1), `shareHoldMinutes` (60), `maxPositionPerStock` (5000), `maxPortfolio` (20000), `maxBondsPerPlayer` (8), `practiceStartingCredits` (10000), `exchangeActionsPerMinute` (20).
  - Companion app and onboarding: `remoteDailySpendLimit` (5000), `remoteDailyGoodsLimit` (5000), `remoteGoodsFloorValue` (10), `remoteModifiedGoodsValue` (500), `giveHandbookOnFirstJoin` (true).
  - Cross-mod API: `siblingCallerDailyBudget` (2500), `siblingCallerBudgets` (empty), `siblingPerPlayerDailyCap` (2000), `siblingMaxSinglePayout` (1000), `siblingTransferFeePercent` (5.0), `sectorBands` (5,10), `reserveAlertLow` (25000), `shockSources` (neroevents), `shockMaxMinutes` (1440), `maxActiveShocks` (64).
- **Cross-mod API (`SiblingEconomy.API_VERSION` 1).** Other mods claim an `EconomyCaller` with a closed set
  of reason codes and then `pay` (Reserve to player), `charge` (player to Reserve), `transfer` (player to
  player, with a fee to the Reserve, `siblingTransferFeePercent`), `canPay`, `remainingToday` and `feeFor`.
  Each payout is held to the caller's own daily budget, the shared `siblingDailyBudget`, a per-player daily
  cap and a per-payout maximum, and is refused before anything moves with a plain `EconomyResult`. A request
  key makes a call idempotent for 24 economy-hours. Ledger rows carry an `origin` (`<modid>/<reason>`), shown
  in the player's own export. Untyped Core deposits still work and count under the label `unknown`.
- **Accounts for other mods.** `ForeignAccountId(kind, value)` names an account a mod keeps, such as a faction
  treasury; credits move in and out with `EconomyCaller.deposit`, `withdraw` and `balance`, and `/eco admin
  supply` lists one line per kind (marked when no mod claims it).
- **Economy events.** `EconomyEvents` for typed listeners: `Sold`, `Bought`, `Filled`, `Dividends` and
  `SiblingPaid`, each carrying one party only, handed out at the end of the economy's server tick.
- **Class-free channels and gates through Core.** Threshold channels `neroeconomy:reserve`,
  `neroeconomy:house_stock`, `neroeconomy:market_shock` and `neroeconomy:sector_index`; six per-player
  progression gates (`first_sale`, `first_purchase`, `first_investment`, `first_bond`,
  `first_offer_accepted`, `trader_100`); and an inbound `<modid>:market_shock_request` channel from the mods in
  `shockSources`, bounded by `shockMaxMinutes` and `maxActiveShocks`.
- **Commodity registration and queries.** `CommodityApi.registerDefault` and `exclude` (data packs always win;
  defaults pass the arbitrage guard and show in `/eco admin reload-check` as `code:<modid>`), price queries
  `referencePrice`, `bid` and `ask`, and sector quotes `ExchangeApi.sectors` and `sector`.
- **Wiki:** pages for trading, auto-trading, the exchange, the Vault, the autonomous economy, demos
  and the Handbook, fair play and data packs.

### Changed

- Crash telemetry is now live: the Sentry DSN is set, so anonymous, scrubbed crash reports (at most 10
  a session) are sent unless `telemetryEnabled=false`. See PRIVACY.md.
- Version set to `0.3.0-beta.1`. An old-world test loads a 0.2.0-alpha.1 save into the combined store, and a
  benchmark (excluded from normal test runs; `-Pbenchmarks`) records the cost of a simulation step, a 72-hour
  catch-up, matching and store size.
- **Credits come from the Reserve, not from nowhere.** Starting balances, Credit Chips, system job
  and bounty payouts, Merchant House and exchange payouts and other mods' untyped deposits are
  transfers from the Reserve, within a daily budget, and a payout it cannot cover is refused.
  Fees go back to the Reserve. Credits are created only by the Reserve's fill and daily top-up, the
  one-time migration of escrow and an operator's grant.
- **Server-funded jobs are funded from the Reserve when posted.** The payout is escrowed at posting
  (it used to be minted at fulfilment) and an expired job returns it to the Reserve. Merchant Houses
  and the server also post contracts and bounties this way.
- **Item claims are now Vault contents.** Goods owed to a player are delivered to their Vault, and
  `maxClaimStacksPerPlayer` bounds the Vault (the smaller of it and `vaultStacks` applies).
  Idle-shop and removed-shop stock goes to the Vault.
- **Market Board listings and buy offers are orders on the book.** They match each other, keep
  their ids, and are cancelled with `/eco market cancel <id>` or `/eco order cancel <id>`.
- **The starting balance is locked** for `startingBalanceVestMinutes` (30) of play time: it can pay
  Merchant Houses and fees but cannot be paid, offered, traded or put into shares and bonds.
- **Credit Chips** pay less across the day (100 %, 80 %, 60 %, 40 %, 20 %), draw on a shared
  `creditChipDailyBudget`, and cannot be redeemed by creative or spectator players.
- **Fees:** a market fee on every sale, a flat listing fee, an auction fee on the winning bid, an
  exchange fee and an optional trade tax; see the wiki for the table. A price modifier changes only
  the buyer's price.
- **Erasure and export cover every section.** Erasing a player destroys their goods and moves their
  escrow, exchange principal and rule budgets to the Reserve, refunds what other players are owed,
  and ends an open trade; `/eco export` gains `vault`, `book`, `offers`, `rules`, `trade_escrow`,
  `auto_traders`, `exchange`, `merchant_houses`, `remote_spend`, `starting_balance_vesting` and
  `handbook_given`.
- **Saving.** The economy store is saved with the game's own save, together with player data and
  chunks. The old save within about a second of an inventory move is gone, because it let a crash
  copy or lose items; a hard kill now rolls player data and store back together.
- **Link schema 2.** The module reports schema 2. Schema 1 sections, the `trade` action and their
  keys are kept for one release. `trade` and its `claim` delivery now mean the Vault.
- **`PRIVACY.md`** describes the combined store, every section, the memory-only data, retention,
  export and erasure of the new data, and states that nothing ranks players by wealth.
- **Gallery.** Its blocks and label stands are recorded, so `gallery clear` removes exactly what it
  placed, and it builds sandboxed sample data only.

### Fixed

- **Wash trading and alternate accounts.** A reference price moves only when at least
  `referenceMinPairs` different pairs of accounts traded, with no pair counting for more than the
  pair ranked `referenceMinPairs` from the top, and a daily reach limit; the pair tally is held in memory only as one-way hashes.
  The arbitrage guard re-runs whenever a reference moves.
- **A stolen app token could drain goods.** Goods leaving an account through the app are now capped
  per day (`remoteDailyGoodsLimit`) apart from credits.
- **Locked starting credits could be laundered** through the exchange (a bond bought and cashed in
  early). Share and bond principal now needs earned credits.
- **The Credit Chip was an unlimited faucet for alternate accounts and creative players.** It now has
  a shared daily budget and refuses creative and spectator players.
- **An Auto-Trader fed by a creative player's hopper** could list free goods; its sell rule now does
  not run while its owner is in the game in creative or spectator mode.
- **An offer inbox could be filled by a few accounts.** A sender may keep at most four open offers
  with the same recipient.
- **The audit trail could drop its mint and burn rows first.** When the row bound is reached, ordinary
  rows go first.
- **Operator credit changes were not all counted.** Every grant, take and set is counted wherever it
  enters (command, Hub or API).
- **A vault slot could keep surplus goods** a non-source player added by clicking; the surplus is
  now handed back.
- **A very large wallet payment** from the Hub passed an unchecked number to the ledger.
- **A crash could duplicate or lose goods** crossing between an inventory and the store (see Changed).

### Migration

- On the first start with 0.3, the four 0.2 stores are read once, adopted as sections of
  `neroeconomy:economy`, and emptied on disk only after the new store has been saved and read back,
  so a crash during the first save cannot lose both copies. They are never imported twice.
- Item claims become Vault contents (delivered, not deposited, so a long claim list is booked in
  full). Board listings and buy offers become orders on the book, with the same ids, prices and
  expiries. Credit escrow that 0.2 had written off the ledger is restored to the escrow account.
- The Reserve is filled once with `reserveInitial` credits. Existing balances are not touched.
- A world whose economy exists but whose store cannot be read **freezes** instead of starting
  empty; an operator can accept a fresh start with `/eco admin health accept`.
- Take a backup of the world before the first start. Do not run 0.2 on a world 0.3 has opened.
- The link module reports schema 2; an older NeroLink app keeps working on the schema 1 keys for one
  release.
- No name in the public `api` package was renamed or removed.

### Audit remediation (earlier in this release)

Audit remediation: the fixes for the October 2026 audit. This pass changes command syntax, the
companion-app payloads and the export file, and adds config keys, so server operators should read
**Changed** before upgrading.

#### Added

- **Seeing and cancelling your own rows.** `/eco market mine` lists your open Market Board
  listings, shop listings, buy offers, jobs and auctions. `/eco market cancel <id>` cancels a board
  listing, a buy offer, an unclaimed job or an auction with no bid, and returns what it held in
  escrow to your claim.
- **Releasing a job.** `/eco contract|delivery|bounty release <id>` hands a claimed job back, and a
  claim now lapses by itself after `jobClaimTimeoutMinutes`.
- **Config keys** (defaults in brackets): `auctionMinIncrementPercent` (5),
  `jobClaimTimeoutMinutes` (120), `shopListingMaxIdleDays` (90), `maxListingsPerPlayer` (64),
  `maxBuyOffersPerPlayer` (32), `maxJobsPerPlayer` (16), `maxAuctionsPerPlayer` (8),
  `maxClaimStacksPerPlayer` (256), `maxStackDataBytes` (8192), `creditChipDailyLimit` (5),
  `systemJobsEnabled` (true) and `systemJobDailyPayoutCap` (5000). The wiki's configuration page
  lists every key with its bounds.
- **`neroeconomy:untradeable` item tag.** Empty by default. An item in it cannot be listed,
  auctioned, put in a shop, requested by a job or buy offer, or used to fill one.
- **Economy clock.** Every deadline and stored timestamp is measured on one persisted clock that
  never runs backwards and moves forward by at most 72 hours between two readings.
- **Recovery backups.** The four world stores load through Neroland Core's backup-and-restore
  guard, which keeps `neroeconomy_ledger_backup.dat`, `neroeconomy_market_backup.dat`,
  `neroeconomy_obligations_backup.dat` and `neroeconomy_shop_owners_backup.dat` beside the primary
  files and restores from them when a primary file cannot be read.
- **Companion app.** Snapshots carry the keys the shipped app reads, buy offers appear in the market
  list and can be filled from the app, a buy works while the player is logged out (the goods wait in
  their item claim), and a `balance` event is published when a balance changes.
- **API.** `PricingEngine.executionPriceWithinQuote` is the price rule purchases now settle under.

#### Changed

- **Job posting syntax.** The target kind is now a word of its own, and ids are typed in full:
  - `contract post item|tag <id> <quantity> <payout>`
  - `delivery post item|tag <id> <quantity> <dimension> <x> <y> <z> <payout>`
  - `bounty post entity <entity type id> <payout> [quantity]`
  - `bounty post player <player> <payout> [quantity]`

  Tag ids are typed without the `#`. Targets are checked against the registries and limited to 64
  characters, and the delivery dimension must exist.
- **Player bounties** need permission level 2 as well as `playerBountiesEnabled`. The player a
  bounty is on cannot claim it.
- **Purchases never cost more than the price you confirmed.** A price that rose after the quote is
  refused; a price that fell is charged at the lower price. `executionPriceTolerance` no longer
  affects purchases; it only serves the older `PricingEngine.executionPriceAccepted` API method.
- **Only unmodified stacks fill a buy offer or fulfil a job.** Renamed, enchanted, filled or damaged
  stacks are refused, and the message says so.
- **Auctions** need each new bid to beat the standing bid by `auctionMinIncrementPercent` (default
  5 %), and always by at least 1 credit.
- **Per-account caps** apply to open board listings, buy offers, jobs, auctions and uncollected
  claim stacks, and a stack carrying more than `maxStackDataBytes` of data cannot be escrowed.
  Refunds, expiry and settlement are never blocked by a cap.
- **Credit Chips** are limited to `creditChipDailyLimit` redemptions per account per day (default
  5; `0` disables redemption).
- **Server-funded jobs** posted through `DeliveryJobApi.postSystem` can be switched off with
  `systemJobsEnabled` and are limited to `systemJobDailyPayoutCap` credits posted per day.
- **Idle shop listings** expire into the owner's item claim after `shopListingMaxIdleDays` (default
  90) without an owner interaction or a sale.
- **`startingBalance`** has a maximum of 1,000,000.
- **The gallery commands** `gallery` and `gallery clear` need permission level 3, creative mode and
  `adminMutationsEnabled`. The rows and shops they seed are demo rows: they hold no escrow, cannot
  be bought or filled, and are hidden from search and from the companion app. `gallery clear`
  removes only gallery blocks, demo rows and entities carrying the gallery tag.
- **Development tooling is no longer shipped.** The `/necgallery` client command registers only in
  a development environment, and the `neroeconomy:capture` dimension and the Fabric game tests are
  left out of every jar.
- **Player Shops.** A level-2 operator can break any shop, and anyone can break a shop that has no
  owner on record. Breaking, replacing or clearing a shop never loses stock: it goes to the owner's
  item claim.
- **Bank Terminal.** The recipient must be an online player or the UUID of someone who has played
  on the server, exactly as for `/eco pay`.
- **Request ids** are remembered for 10 minutes and survive a restart, so a replayed purchase,
  payment or job action is refused across a restart too.
- **Command output.** History rows show a date, and job, auction and `market mine` rows show the
  time remaining, instead of raw numbers and enum names.
- **Companion-app module (still schema 1).**
  - `transactions.nextCursor` is now a **string** and is left out on the last page. It used to be a
    number, with `-1` on the last page. This is a deliberate break: the shipped app reads a string.
  - `trade` requires `requestId`; a missing or malformed one is refused. `qty` must be a whole
    number from 1 to 64.
  - `trade` with `op: "sell"` and no `unitPrice` fills the buy offer named by `listingId`. With
    `unitPrice` it still posts a new listing.
  - A successful `trade` result carries `op`, `listingId`, `qty`, `price`, `total`, `filled` and
    `delivery` beside the balance object.
  - Error messages are plain sentences. They used to be result names such as `OUT_OF_STOCK`.
  - Snapshots and actions are rate-limited. A throttled snapshot returns the last one served with
    `throttled: true`.
  - Item names are base names, never a custom (renamed) name, and alerts are four fixed sentences
    with one stable id per kind, so a new alert replaces the previous one of its kind.
- **`/eco export` output.** The file keeps its ledger keys at the top level and adds
  `account_reference`, `credit_chip_redemptions`, `economy_time`, `wall_time`, `market`,
  `obligations` and `shops`. It is no longer cut at `historyLimitPerPlayer`. The other party of a
  transaction row is written as `counterparty` instead of that party's pseudonym, and times are
  economy-clock times. The file is written owner-only where the file system supports it.
- **Requires Neroland Core 1.13.0** (unchanged pin), now for its `SavedDataRecovery` backup guard
  as well.

#### Removed

- The unused `ShopSettlement` class and the mod's local copy of `SavedDataRecovery` (Core's is used
  instead).
- The `syncModels` Gradle task, which called a script that does not exist.

#### Fixed (audit)

Jobs, bounties and auctions:

- Contracts, deliveries and bounties could not be posted with a usable target, because the command
  rejected `:` and `#`. A posted job could never be fulfilled and its payout was locked until
  expiry.
- A job with a very long target could disconnect anyone who opened the jobs tab.
- A claimed job stayed locked to its claimant until it expired.
- Bids of one extra credit could extend an auction's anti-snipe window indefinitely.
- `playerBountiesEnabled` was described as permission-gated but had no gate.
- A player-target bounty could show the target as `player:<uuid>`; lists now show a fixed phrase.

Market and terminals:

- A buyer could be charged up to the execution tolerance above the price they confirmed.
- A shop owner could swap the item between a buyer's look and click; a purchase now carries the
  item the buyer saw and is refused if it changed.
- Buy offers and jobs matched by item id only, so a nearly broken tool, a renamed item or a filled
  container satisfied an offer for the plain item.
- A buy offer for an item id that does not exist held its credits in escrow until expiry.
- Board listings, buy offers, jobs and auctions had no cancel path and no per-account limit, and a
  listed stack had no size limit.
- Request ids were kept in memory only and were used up before the request was validated.
- Collecting a claim in creative mode with a full inventory destroyed the claim.
- Each open terminal ran several full market scans a second; a query now does one pass.

Player Shops:

- A shop removed by an explosion or a command kept its ownership row, so the next shop placed there
  belonged to the previous owner.
- After its owner's data was erased, a shop could not be broken by anyone.
- `/setblock`, `/fill`, `/clone` and structure placement over a shop deleted its listing and stock.
- Shop listings never expired, even for owners who had left.

Bank Terminal:

- The terminal paid any well-formed UUID and opened the recipient's account before checking funds,
  so a player with no money could create unlimited funded accounts and audit rows. It now refuses
  an unknown recipient and a short balance with a specific message and opens no account.

Screens and packets:

- Balances and prices above 32,767 displayed wrongly, and a shop priced at 32,768 or more could not
  be bought from.
- Typing the inventory key (default `e`) in a search, recipient or amount box closed the screen.
- No packet had a rate limit. Each player now has a budget (queries: burst of 10, 5 per second;
  value-moving actions: burst of 6, 2 per second), and an over-budget packet is dropped silently.
- Packet handlers did not check that the player was alive, not a spectator and in the block's
  dimension. Spectators can open a terminal but cannot act through it.
- Countdown timers used the client's clock, and received pages lingered after a screen closed.
- Thirteen hard-coded English strings and several raw enum names are now translatable.

Money supply:

- The Credit Chip was an uncapped, automatable source of credits; it now has a daily limit.
- The Credit Chip's meteor entry used keys Neroland Core does not read, so it never dropped from
  meteors. It now does when Nerospace is installed.
- Server-funded jobs were always enabled although documented as optional.
- `startingBalance` accepted values so large that no deposit could succeed.

Clock and persistence:

- Deadlines used the system clock: a forward jump expired everything at once and a backward jump
  stalled the expiry and retention sweeps.
- A store whose file could not be read was replaced by an empty one, with no backup.
- A crash shortly after a claim was collected could offer the same claim again. The economy stores
  are now saved within a second of a collect.
- An exception thrown by another mod's currency listener could interrupt a trade between the debit
  and the escrow write.

Privacy:

- `/eco export` covered the ledger only and stopped at `historyLimitPerPlayer` rows. It now covers
  the ledger, market, obligations and shops.
- An export contained the other party's pseudonym.
- Export files were only swept after 24 hours of uptime, so a server that restarted daily never
  deleted them. They are now swept at start as well, and written owner-only where possible.
- Erasure left bounties that targeted the erased player in place, did not clear the alert limiter,
  and walked the ledger twice.
- The alert limiter kept player-keyed entries across worlds, and alert ids embedded a timestamp, so
  a player's alert list grew without bound.
- Telemetry (still inert) would have included a player's UUID in the message of a failed
  export-file operation. UUID-shaped text is now scrubbed and file failures report the exception
  class only.
- `PRIVACY.md` named no contact and no responsible party, and described the logging opt-out, the
  erasure tombstone, retention of settled jobs and stored coordinates incorrectly or not at all.

Companion app:

- The market tab was always empty, history failed to load and every sell was refused, because the
  module and the app disagreed on field names.
- There were no live balance updates, no action worked for a logged-out player, and a retried buy
  without a request id became a second purchase.

Commands and packaging:

- Any creative-mode player could run `gallery`, which seeded real stock and credits into the live
  market, and `gallery clear`, which cleared a large area and discarded the entities in it.
- The `neroeconomy:capture` dimension was added to every world, and the `/necgallery` command and
  the game-test entry point shipped in release jars.

Documentation:

- Stale version, Core and Minecraft-matrix strings were corrected, and the wiki now gives the full
  command syntax, every config key, the companion-app payloads and an accurate privacy page.

## [0.1.0-alpha.1] - 2026-09-20

Minecraft **26.3** support, together with the terminal overhaul and gallery tooling that landed
after 0.0.1-alpha.1. No item, block or tag id and no config key changed. An earlier version of this
entry said "No gameplay, id, tag or config change"; that was wrong, because block placement, the
screens and the command tree changed and a dimension was added, as listed below.

### Added

- **Minecraft 26.3** as a new Stonecutter node on every loader — NeoForge `26.3.0.7-beta`,
  Forge `26.3-66.0.2` and Fabric (fabric-api `0.161.0+26.3`, NeoForm `26.3-1`) — built alongside
  26.1.2 and 26.2, so every release now ships **nine** loader × version jars.
- **Terminal overhaul.** The Bank Terminal, Trading Terminal, Market Board and Player Shop face the
  player who places them and can be rotated and mirrored, with new multi-part models and textures.
  All four screens were rebuilt on a shared textured base with new layouts, labels, a selectable
  results list and board-specific controls.
- **`/neroeconomy` command root**, a third name for the `/eco` and `/economy` tree.
- **Gallery capture harness.** `/neroeconomy gallery` and `/neroeconomy gallery clear` build and
  remove a showcase scene, and the client command `/necgallery capture` photographs it for the
  listing gallery. A `compressScreenshots` Gradle task and the gallery workflow publish the shots.
- **`neroeconomy:capture` dimension**, a flat backdrop for the capture harness. It was added to
  every world by this release. A later release restricts the gallery commands and stops shipping
  the dimension and `/necgallery`.

### Changed

- VS Code run/debug configurations (`.vscode/launch.json`, `.vscode/tasks.json`) gain the three
  26.3 cells; the "Build all" task now builds all nine.
- CI (`multiloader.yml`, `publish.yml`) builds, attaches and publishes the 26.3 jars.
- Requires **Neroland Core 1.13.0** (was `1.10.0`) — the first Core release with a 26.3
  build. The loader range still derives from the pin (`[${nerolandcore_version},2.0)`).
- JEI pins moved to the newest published builds on each Minecraft version: `29.40.0.101` (26.1.2), `30.35.0.223` (26.2) and `31.3.0.18` (26.3). Compile-time API only — JEI remains a soft dependency and the shipped jar gains no hard requirement.

### 26.3 port notes

- Block classes build their codecs through Core's `BlockCodecs` (26.3 removed block-type codecs); `codec()` is kept without `@Override` so one source compiles on every version.
- Build: the shared `common/` Java source is now preprocessed by Stonecutter for every non-active node (`stonecutterProcessCommon`), so common code can carry `//? if >=26.3 {` blocks, and `common/src/main/resources-<mc>` overlay folders are merged over the shared resources for matching nodes (`mergeCommonResources`). The active node still compiles the raw `common/` folder.
- Build plugins aligned with Neroland Core: ModDevGradle `2.0.147` (the older 2.0.141 cannot set up NeoForge 26.3), ForgeGradle `7.0.40`, Stonecutter `0.9.8`.
- NeoForge metadata: the deprecated `logoFile` property is replaced by `iconFile` on 26.2+ (the logo is a square 256x256 PNG) while 26.1.2, whose FML only understands the old key, still gets `logoFile` — the key is chosen per cell when the manifest is expanded. This clears NeoForge 26.2+'s dev-only "uses the deprecated `logoFile` property" warning screen. The Forge manifest is unchanged: `logoFile` is still the only key Forge supports.
